# Private copied-world validation

The runner loads an existing chunked Valheim world in an isolated local host, using the native SaveSystem world discovery. It never joins the original dedicated server. Supply an entire world directory, including its completed _main save generation, .ok marker, .chunks index, .fwl2/.db2 metadata and all .chunk files; do not copy only a .db file.

Obtain a stable snapshot externally, comparing remote hashes before/after the transfer and checking every local file. Keep snapshots and receipts under ignored dist/private-worlds. The runner makes another private working copy under each run's saves/worlds_local before launching; the snapshot itself is not the save target and its hashes are checked again afterwards. No user character is copied: a disposable profile is created. Cloud saving is disabled and Utils.GetSaveDataPath routed to that run. No server restart or world-file modification on the original server is required.

```powershell
./tools/WorldBenchmark/run.ps1 -GamePath GAME_DIRECTORY -WorldDirectory PRIVATE_WORLD_DIRECTORY -ClientPack COMPLETE_CLIENT_ZIP -Profile FarLands
./tools/WorldBenchmark/run.ps1 -GamePath GAME_DIRECTORY -WorldDirectory PRIVATE_WORLD_DIRECTORY -ClientPack COMPLETE_CLIENT_ZIP -Profile NativeFog
./tools/WorldBenchmark/run.ps1 -GamePath GAME_DIRECTORY -WorldDirectory PRIVATE_WORLD_DIRECTORY -ClientPack COMPLETE_CLIENT_ZIP -Profile ClearFog
```

All profiles use the same pack and a fresh private client/cache/world copy. FarLands is the default reference: its DLL from the pack is activated only inside the isolated client, terrain 4000 m, forest 2500 m, own buildings off (VEE remains enabled), HorizonClarity off and FarLands air at its defaults. The probe waits for FarLands terrain and forest completion before warmup and fails on its failure flags. This reference compares the full FarLands rendering/air, not fog alone. NativeFog and ClearFog require FarLands disabled in the supplied pack. ProgressiveMap is disabled in every run to exclude deferred map preparation from the scene sample; all other included plugins remain in place. NativeFog disables HorizonClarity, ClearFog enables its default 0.25/4000 configuration. NativeFog versus ClearFog isolates HorizonClarity; FarLands provides the requested long-distance reference. No profile is vanilla without all mods.

The isolated probe disables local pause so a hidden window keeps simulating. The probe finds the player-built workbench nearest world origin, skips the disposable introduction, teleports the player there, retries placement if the introduction respawn replaces the player, waits until teleport/zone loading finish, fixes the view above it, sets Clear weather and midday locally, warms up for 60 s, samples 15 s, and records a PNG plus frame times. This may be a different base/view from the player's screenshot. Water, wind/animation and streaming progress can still differ. Warmup is fixed and does not guarantee distant VEE reconstruction has finished. A newly loaded local host also simulates the world, unlike a normal client on the dedicated server.

**Timing is provisional.** The runner uses a hidden 1280x720 window and records performanceRepresentative=false. Occlusion can affect frame pacing, and -AllowConcurrentClient allows additional CPU/GPU contention. These numbers must not be presented as the player's real FPS or proof of improvement. A PASS proves the world loaded and the script completed; inspect each PNG before treating a render as valid. In the first trial, screen capture was unusable despite a completed load; the runner now uses explicit native-camera RenderTexture capture. This also differs from the final on-screen UI/composite. Real representative performance still requires foreground, matched resolution/settings and no parallel client, repeated after streaming settles.

Reports, screenshots, world identities and logs remain under dist/world-benchmark; never commit or publish these files. Only the runner/probe and generic methodology belong in Git. Display registry values are saved/restored even on failed runs; the runner may terminate only its own child. No plugin or configuration is installed in the normal game.

Validated locally on 2026-11-14 with Valheim 1.0.21: the corrected ClearFog run loaded the copied world, completed teleport/zone checks, produced an inspected 1280x720 coastal construction render, preserved snapshot hashes and restored display preferences. Fog density was 0.00075; the native camera already had far clip 20000 m, so HorizonClarity's 4000 m minimum did not extend it. This confirms scene loading and fog application, not new distant terrain or representative FPS.

NativeFog and FarLands reference runs also completed on the same snapshot and anchor. All three PNGs were inspected; FarLands reported terrain/forest complete before sampling. Its reference DLL SHA-256 is b81d9c266e2b8eafc7b137ed063c85e3caf0dd9054bb5dbacee86ad237fbacb2 (1.3.0). Effective configuration/DLL hashes are retained beside each report. Captures show scene geometry but retain dithering/grain and camera-only composition artifacts; do not treat them as pixel-identical final-screen renders. No comparative FPS claim is validated.
